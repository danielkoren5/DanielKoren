# מוקד — CRM MVP

מערכת CRM בעברית (RTL) לניהול לקוחות, צנרת עסקאות ומשימות, בנויה כ-MVP
עבור עסק ייעוץ עסקי. זהו שלב 1 במפת דרכים רחבה יותר שכוללת אוטומציות, בוט
WhatsApp ואינטגרציות חיוב/הנהלת חשבונות — ראו "מפת דרכים" למטה.

## סטאק טכנולוגי

- **Next.js 16** (App Router, React Server Components + Server Actions)
- **TypeScript**, **Tailwind CSS v4**
- **Prisma 6** + **SQLite** לפיתוח מקומי (מוכן למעבר ל-PostgreSQL לפרודקשן)
- גופנים עצמאיים (Rubik + Heebo, Hebrew + Latin subsets) — בלי תלות ברשת

## הפעלה מקומית

דרישה מקדימה: Node.js 20 ומעלה.

```bash
npm install
npm run dev     # http://localhost:3000
```

זהו. `npm install` יוצר את `.env` (מתוך `.env.example`) ומייצר את קליינט
Prisma, ו-`npm run dev` מריץ את המיגרציות לפני שהשרת עולה. המערכת עולה
ריקה — עם שלבי הצנרת המוגדרים כברירת מחדל ובלי נתונים מומצאים.

### נתוני דוגמה (אופציונלי)

כדי למלא את המערכת ב-7 לקוחות ו-7 עסקאות לצורך התרשמות:

```bash
npm run db:seed
```

שימו לב: `db:seed` **מוחק** את כל הנתונים הקיימים וזורע מחדש. אל תריצו
אותו אחרי שהזנתם נתונים אמיתיים.

## מבנה הנתונים

כל מודל נושא `tenantId`, גם שהיום יש דייר (tenant) יחיד — כך שמעבר עתידי
למוצר רב-דיירים (multi-tenant SaaS) הוא מיגרציית נתונים, לא כתיבה מחדש של
הסכימה.

מודלים עיקריים (`prisma/schema.prisma`): `Tenant`, `User`, `Stage`,
`Contact`, `Tag`, `Deal`, `Activity` (ציר זמן), `Task`.

שלבי הצנרת (`Stage`) מותאמים למחזור חיים של ליווי ייעוצי, לא למכירה
קמעונאית גנרית: ליד חדש ← שיחת אבחון ← הצעת שירות ← חוזה נחתם ← ליווי פעיל
← הסתיים / חידוש.

## מה יש היום (MVP)

- **לוח בקרה** — שווי צנרת פתוחה, עסקאות שנסגרו, לקוחות, משימות פתוחות,
  תרשים צנרת לפי שלב, פעילות אחרונה, משימות קרובות.
- **לקוחות** — רשימה, הוספה, כרטיס לקוח 360 (פרטים, תגיות, עסקאות, ציר
  זמן, משימות פתוחות).
- **צנרת עסקאות** — תצוגת קנבן לפי שלב, יצירת עסקה, העברת עסקה בין שלבים.
- **משימות** — יצירה, שיוך ללקוח/אחראי, סימון כהושלמה.

עמודי **אוטומציות**, **בוט ושיחות**, **חיוב וחשבונות** ו**דוחות** קיימים
כ"בקרוב" עם תיאור מה מתוכנן, כדי לשקף את מפת הדרכים בתוך המוצר עצמו.

## מפת דרכים

1. ✅ ליבת CRM (MVP הנוכחי)
2. מנוע אוטומציות — טריגרים/תנאים/פעולות
3. בוט WhatsApp Business Cloud API
4. אינטגרציית חיוב ראשונה (למשל Green Invoice) + ייבוא נתונים מ-LeadMeCMS
   (ידרוש אוטומציית דפדפן, אין API רשמי) ומקור CSV נוסף
5. יומן + מייל + תזכורות אוטומטיות סביב פגישות
6. (לפי הצורך) מעבר ל-multi-tenant מלא

## החלטות עיצוב

- **מוכן ל-multi-tenant בלי לבנות עכשיו** — `tenantId` בכל טבלה, דייר יחיד
  בפועל.
- **SQLite בפיתוח** — אין תלות בשירות חיצוני להרצה מקומית; להחלפה ל-Postgres
  משנים את `provider` ב-`prisma/schema.prisma` ואת `DATABASE_URL`.
- **Server Actions** במקום שכבת API נפרדת — פחות קוד גבולות (boilerplate)
  ב-MVP; אם יתווסף לקוח חיצוני (אפליקציית מובייל, אינטגרציה חיצונית) יהיה
  צורך בשכבת API מפורשת.
